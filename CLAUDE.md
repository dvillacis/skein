# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`skein` (PyPI `skein-glm`) is a Rust core + Python API for weighted
structured nonconvex sparse models — group MCP/SCAD, sparse-group
nonconvex, graphical lasso family, etc. The Rust crates do all the
numerics; the Python package is a sklearn-compatible facade over PyO3
bindings.

Current shipping version: **v0.10.0**. `ROADMAP.md` is the authoritative
milestone plan and status table; `README.md` is the public-facing pitch
and headline benchmark numbers; `CHANGELOG.md` is the per-release
narrative. Don't restate any of those here.

## Build & test

```bash
# Rust-only loop (fastest for algorithm work; no Python rebuild)
cargo test -p skein-core --lib
cargo test -p skein-core test_name -- --nocapture   # single test

# Full Python package — required after changing any Rust touched by PyO3
# Always pass --features=blas-accelerate (macOS) / --features=blas-openblas (Linux)
# for benchmarking or any wall-clock comparison — without it ndarray's matvec /
# rmatvec / dot fall back to a naive Rust loop and the prox-Newton GLM hot path
# is ~3× slower. Shipped wheels enable BLAS in `.github/workflows/wheels.yml`.
maturin develop --release --features=blas-accelerate   # macOS release build
maturin develop --release --features=blas-openblas     # Linux release build
maturin develop                                        # dev profile (no BLAS); ~10× faster build for iteration
pytest                           # all python tests
pytest tests/test_smoke.py -k name_substring   # single test

# Pre-PR checks (mirror CI, in order)
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test -p skein-core --lib solve_path_screening_on_matches_screening_off_within_tol -- --nocapture
cargo test -p skein-core --lib              # the rust gate; workspace test is NOT a gate
maturin develop --release --features=blas-accelerate   # or blas-openblas on Linux
ruff check python/ tests/
mypy python/
pytest tests/                                # ~8 s on a warm cache
sphinx-build -W -b html docs docs/_build/html   # docs build is -W (warnings = errors)
```

**What CI actually runs** (`.github/workflows/ci.yml`): a `rust` job on
ubuntu + macos with the five rust steps above (fmt → clippy → solver
pre-flight → `cargo test -p skein-core --lib`), and a `python` job on
ubuntu + macos × {3.10, 3.11, 3.12} that does `pip install -e ".[dev]"`
(which triggers maturin under `MATURIN_PEP517_ARGS="--profile dev"`) →
import smoke → ruff → mypy → pytest. The workspace-level `cargo test`
is **not** the gate, and the PyO3 bindings crate has no standalone Rust
tests (exercised via pytest after `maturin develop`). The `bench-smoke`
workflow runs two `benches/v2` cells per PR to catch pipeline breakage;
the `wheels.yml` workflow builds + publishes on tag push.

## Benchmarks

Two coexisting harnesses, plus a Rust microbench tree:

- **`benches/`** — v1 cross-package harness (skein vs sklearn / skglm /
  celer / glmnet / ncvreg / grpreg). Snapshots in
  `benches/results/*.json` are committed and `host_id`-tagged — do not
  overwrite snapshots from a different host. R comparators are
  non-fatal: missing R skips the runner with a warning.

  ```bash
  python benches/run.py --scenarios mcp_ls mcp_ls_sparse --sizes small,medium
  ```

- **`benches/v2/`** — publication-quality Snakemake suite backing the
  software paper. Produces JSONL aggregates → figures + tables under
  `paper/`. Driven by `benches/v2/config.yaml`; bench extras live in
  `pyproject.toml`'s `[project.optional-dependencies]` `bench` group.

  ```bash
  pip install -e '.[bench]'
  maturin develop --release --features=blas-accelerate   # or blas-openblas on Linux
  cd benches/v2 && snakemake --profile profiles/m1-headline
  ```

  Committed snapshots assume a BLAS build (matches the shipped wheel
  configuration). A no-BLAS rebuild of the same cells runs ~3× slower
  on the Poisson / logistic GLMs — don't refresh snapshots from a
  default `maturin develop --release` run.

  CI smoke (`.github/workflows/bench-smoke.yml`) runs two cells per PR
  to catch pipeline breakage. The full headline matrix is a
  maintainer-driven overnight job, not a per-PR check.

- **`crates/skein-core/benches/`** — internal criterion microbench tree
  (block-CD scenarios). Don't conflate with either above.

`paper/` holds the bundle output (figures + tables) regenerated by the
v2 suite — never edit those files by hand. `paper/BUNDLE.md` is the
artifact provenance manifest; `paper/manifest.json` is the machine-
readable index.

## Architecture

The whole library is structured around four traits and one solver
family. Read these before adding a penalty, datafit, or design backend.

**Traits** (`crates/skein-core/src/{datafit,design,penalty,groups}/`):

- `DesignMatrix` — column-access abstraction. Concrete impls:
  `DenseMatrix`, `SparseCSC`, `Standardized<D>` (lazy column
  centering/scaling wrapper), `MmapMatrix` (f64/f32), `Chunked<D>`
  (row-block streaming), `Augmented<D>` (elastic-net `[X; √λ₂ I]`
  trick), `MultiTaskDesign<D>` (multi-response virtual stacking).
  Wrappers compose: e.g. `Standardized<SparseCSC>`,
  `MultiTaskDesign<Standardized<DenseMatrix>>`.
- `Datafit` — exposes coordinate gradient + Lipschitz constants used by
  CD. `GlmDatafit` extends with a weighted-LS surrogate so the LS inner
  solvers absorb every GLM unchanged. Impls: `LeastSquares`,
  `BinomialLogit`, `PoissonLog`, `CoxPh` (Breslow + Efron),
  `MultinomialLogit`, `Huber`, `GramLeastSquares`.
- `Penalty` (scalar) / `GroupPenalty` (block) — prox + threshold logic.
  `mcp`, `scad`, `elastic_net`, `group_lasso`, `group_mcp`,
  `group_elastic_net`, `sparse_group_lasso`. Nonconvex group variants
  (`group_mcp`, group/sparse-group SCAD) are handled by the LLA outer
  loop, not as `GroupPenalty` impls.

**Solvers** (`crates/skein-core/src/solver/`):

- `cd.rs`, `path.rs` — separable-penalty CD + path solver with strong
  rule, gap-safe screening, Anderson acceleration, KKT-based stopping
  in coefficient space (not relative-objective; the latter plateaus
  while β is still moving).
- `block_cd.rs`, `block_path.rs` — group block-CD + path.
- `lla.rs`, `path_lla.rs`, `block_path_lla.rs` — LLA outer loop that
  reduces nonconvex (group) MCP/SCAD to a sequence of weighted convex
  inner problems.
- `prox_newton.rs`, `prox_newton_block.rs` — GLM dispatch (uses
  `GlmDatafit`'s weighted-LS surrogate).
- `glasso.rs`, `glasso_admm.rs` — graphical lasso family + joint
  (Danaher–Wang–Witten ADMM for multi-population fits).

**Python facade** (`python/skein_glm/`):

- `_core.abi3.so` — PyO3 module exporting one `solve_*_path` function
  per (datafit × penalty × design) combination. There are ~60 of these;
  the naming pattern is `solve_<datafit?>_<penalty>_<dense|sparse>_path`.
  The Python estimators dispatch to the right one.
- `estimators.py` — every public sklearn-compatible class (`*Regressor`
  / `*PathRegressor` / `*PathCV`). Naming is `(Datafit)(Penalty)(Path?)Regressor`.
- `penalties.py`, `datafits.py` — Python ABC mirrors of the Rust traits,
  for downstream extension.
- `cv.py`, `ic.py`, `stability.py`, `adaptive.py`, `debiased.py`,
  `multinomial.py`, `multitask.py`, `mmap.py`, `graph_selection.py`,
  `graph_stability.py` — model-selection / inference layers (CV,
  AIC/BIC/EBIC, stability selection, debiased lasso / GLM, adaptive
  weights, edge stability, etc.).

The Rust traits and their Python ABC mirrors are the **extension
surface** — downstream per-paper projects subclass them.

## Solver-change pre-flight (important)

Before modifying any outer convergence logic — `report.converged`, the
outer KKT-loop `break` in `solve_path`, `cd_solve_subset`'s
`max_delta < tol` check, or any `g < f(tol)` formula where `f` is
nontrivial — first run **one** tight-tol test in isolation:

```bash
cargo test -p skein-core --lib solve_path_screening_on_matches_screening_off_within_tol -- --nocapture
```

This test pins `cd.tol = 1e-12` and runs the path solver under
`Screening::{Off, Strong}`. Confirm it terminates in seconds, **then**
run the full suite. Cargo runs tests in parallel; a single unreachable
threshold (e.g. `gap < tol²` becoming `1e-24`) makes `solve_path` sweep
`max_iter × n_lambdas` per test and starves every core indefinitely.

## Conventions worth knowing

- **Stable Rust API contract** — `skein-core`'s public surface (re-exports
  in `lib.rs`) is part of the v0.x stability promise per ROADMAP M8.
  Renaming or signature-changing those types is a deliberate breaking
  change, not a refactor.
- **Standardization** follows glmnet/ncvreg: scale relative to column
  mean even when not centering; intercept recovered as
  `α = ȳ − Σ_j β_j · x̄_j`. The `Standardized<D>` wrapper does this
  lazily — solvers operate in standardized space, results destandardize
  on the way out. The bijection helper is
  `rescale_weights_for_standardize`.
- **BLAS** is feature-gated: `blas-accelerate` (macOS) and
  `blas-openblas` (Linux). `lib.rs` has explicit `use accelerate_src as _;`
  / `use openblas_src as _;` linkage anchors — without them rustc's
  dead-code prune drops the link line. Don't remove. Always pass the
  feature flag for release / benchmark builds — the default
  `maturin develop --release` falls back to ndarray's pure-Rust matvec
  kernels, which on the Poisson GLM bench cost ~3× wall-clock.
- **`maturin develop` profile** — release build is slow (LTO + full
  ndarray/pyo3 set). CI uses `MATURIN_PEP517_ARGS="--profile dev"`. Local
  iteration is fine in dev profile; benchmark with release.
- **Per-feature / per-group weights** are wired through every solver —
  not an afterthought. New penalties should honor `weights_feature` /
  `weights_group` from the start (it's how M5.x adaptive and stability
  selection compose for free).
- **PyO3 GIL release** — every path-solver builder in `crates/skein-py/src/lib.rs`
  wraps the Rust call in `py.allow_threads(|| ...)`. That's what makes
  joblib-threaded CV / stability selection actually parallel. Preserve
  the pattern when adding new builders, otherwise the GIL serializes
  every fold.
- **Regime naming** — bench code uses `deep` for the dense-tail
  regime (`λ_min/λ_max = 1e-3`, active set saturates near λ_min) and
  `sparse` for the support-recovery regime (`5e-2`, active set stays
  at true support). User-facing prose says "dense" instead of "deep"
  to describe what the *solution* does at the tail; the internal key
  stays `deep` for back-compat with committed snapshots.

## Releases

A release is `git tag v$X.$Y.$Z && git push origin v$X.$Y.$Z`. The tag
push triggers `wheels.yml` to build cibuildwheel wheels for Linux
(x86_64 + aarch64), macOS (arm64 + x86_64), and Windows (AMD64), and
publish to PyPI via Trusted Publishers (no API token — the `pending`
publisher trick is documented in the workflow header). **The tag push
is the irreversible step. Do not push a tag until every CI gate is
verified green.**

Semver policy (per `docs/extending/rust-api.md`): we're 0.x, so any
release may break incidental `pub` items. New trait methods with
non-trivial `None`/default impls bump the **minor**; bug fixes bump the
**patch**. The public surface re-exported in `lib.rs` follows the v0.x
stability promise per ROADMAP M8.

### Release-prep checklist

1. **Bump versions.** Both files must move together:
   - `Cargo.toml` → `[workspace.package] version = "X.Y.Z"`
   - `pyproject.toml` → `[project] version = "X.Y.Z"`
   - Run `cargo check` once to refresh `Cargo.lock` (the workspace
     bump propagates to `skein-core` and `skein-py`).
2. **Move the CHANGELOG.** Rename `## [Unreleased]` to
   `## [X.Y.Z] — YYYY-MM-DD`. Date is the calendar date of the tag,
   not the implementation date. Don't leave an empty `[Unreleased]`
   header behind.
3. **Update version pointers.** The one-line status line in this file
   ("Current shipping version: vX.Y.Z") and any matching line in
   `docs/index.md` / `README.md`.
4. **Verify CI locally on HEAD (not your working tree).** See below.
5. **Commit the release.** Subject `release(vX.Y.Z): ...`. Body
   summarises the major work + a `git tag` reminder.
6. **Tag and push** — `git tag vX.Y.Z && git push origin main vX.Y.Z`.
   Watch the `wheels.yml` run; the PyPI publish job is gated by `if:`
   so a failed build won't ship a half-broken wheel.

### Verifying CI locally — gotchas from past misses

The whole point of local verification is to fail fast before the tag
push. Two failure modes have bitten us, both of which CI catches but
local-only runs miss:

**(1) `cargo fmt --check` and `cargo clippy` must run against HEAD,
not your working tree.** Working trees accumulate ad-hoc fmt fixes
across sessions (rustfmt sweeps every `.rs` file in the workspace, not
just the ones you've touched), so a green `cargo fmt --check` locally
doesn't prove that the *committed* state passes. Before the tag push:

```bash
git stash -u                                    # park working-tree changes
cargo fmt --all -- --check                      # against HEAD only
cargo clippy --workspace --all-targets -- -D warnings
git stash pop                                   # restore working tree
```

If either step fails on HEAD, you have an unstaged fmt/clippy fix
floating in your working tree that needs its own commit before the
release commit lands.

**(2) Run pytest against the Python version + scipy version CI uses.**
The CI matrix is `{3.10, 3.11, 3.12}`. Python 3.10 pip-installs scipy
≤ 1.15.x (scipy 1.16+ dropped 3.10 support); local Python 3.12 pulls
scipy 1.17+. Several scipy upstream bugs differ between those versions
(e.g. `multivariate_normal.cdf` returns NaN on `-np.inf` input in 1.15,
fixed in 1.16). To reproduce the 3.10 environment:

```bash
python3.10 -m venv /tmp/skein_py310
/tmp/skein_py310/bin/pip install --upgrade pip
/tmp/skein_py310/bin/pip install -e ".[dev]"   # or pip install numpy scipy scikit-learn pytest for a Python-only smoke
/tmp/skein_py310/bin/pytest tests/
```

**Full local CI sequence** (in order — same as `.github/workflows/ci.yml`):

```bash
# Rust job — run on HEAD via the stash trick above.
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test -p skein-core --lib solve_path_screening_on_matches_screening_off_within_tol -- --nocapture
cargo test -p skein-core --lib

# Python job — every Python version in the CI matrix.
maturin develop --release --features=blas-accelerate
ruff check python/ tests/
mypy python/
python - <<'PY'                                 # import smoke (CI literal)
import skein_glm
for name in ("MCPRegressor", "SCADRegressor", "GroupLassoRegressor",
             "GroupMCPRegressor", "LogisticLassoRegressor",
             "PoissonLassoRegressor"):
    assert hasattr(skein_glm, name)
print("ok")
PY
pytest tests/

# Docs gate.
sphinx-build -W -b html docs docs/_build/html
```

Only after **all of the above are green on HEAD** push the tag.
